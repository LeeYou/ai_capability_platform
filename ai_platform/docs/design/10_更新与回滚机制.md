# 10 — 更新与回滚机制

## 10.1 三类更新

| 更新类型 | 涉及文件 | 触发方式 | 是否需要重启 |
|---------|---------|---------|-------------|
| **License 更新** | `license.dat` | 自动检测 / admin API | 否 |
| **模型更新** | 模型目录 (`model.onnx`, `manifest.yaml`, ...) | admin API | 否 |
| **SO 插件更新** | `libcap_xxx.so` | admin API | 否 |

对于单能力 SDK 交付（Linux SO / JNI / Windows DLL），更新原则保持一致，但由 SDK 包更新工具执行，不依赖 HTTP 管理接口。

核心原则：**全部支持热更新，无需重启容器。**

## 10.2 版本化存放规范

### 10.2.1 模型版本目录

```
/opt/ai_platform/models/face_detect/
├── current -> v3               ← 软链接，指向当前生效版本
├── v1/                         ← 历史版本 (可保留用于回滚)
│   ├── manifest.yaml
│   ├── model.onnx
│   ├── config.yaml
│   └── checksum.sha256
├── v2/                         ← 历史版本
│   └── ...
└── v3/                         ← 当前版本
    ├── manifest.yaml
    ├── model.onnx
    ├── config.yaml
    └── checksum.sha256
```

### 10.2.2 SO 插件版本目录

```
/opt/ai_platform/plugins/
├── libcap_face_detect.so       ← 当前生效 SO (直接文件或软链接)
├── .versions/                  ← 历史版本存档
│   ├── libcap_face_detect.so.1.0.0
│   ├── libcap_face_detect.so.1.1.0
│   └── libcap_face_detect.so.1.2.0
└── .active                     ← 版本记录文件 (JSON)
```

`.active` 文件格式：

```json
{
    "face_detect": {
        "current_version": "1.2.0",
        "so_file": "libcap_face_detect.so",
        "previous_version": "1.1.0",
        "updated_at": "2026-03-26T10:00:00Z"
    }
}
```

### 10.2.3 License 版本

```
/opt/ai_platform/license/
├── license.dat                 ← 当前 License
├── machine_fingerprint.txt     ← 机器指纹
└── .backup/                    ← 历史 License 备份
    ├── license.dat.20260301
    └── license.dat.20260601
```

## 10.3 模型更新完整流程

```
管理员操作:
│
├── 1. 将新模型包上传到宿主机
│   └── 放入 /opt/ai_platform/models/face_detect/v3/
│   └── 包含 manifest.yaml, model.onnx, config.yaml, checksum.sha256
│
├── 2. 更新 current 软链接
│   └── cd /opt/ai_platform/models/face_detect
│   └── ln -sfn v3 current
│
├── 3. 触发 reload
│   └── POST /api/v1/admin/reload
│       { "capability_id": "face_detect", "type": "model" }
│
└── 4. 平台自动执行:
    │
    ├── a. 解析新模型目录
    │   └── 读取 /opt/ai_platform/models/face_detect/current/
    │
    ├── b. 预校验
    │   ├── 读取 manifest.yaml
    │   ├── 校验 checksum.sha256
    │   ├── 检查 API 版本兼容性
    │   └── 任一失败 → 返回错误，不执行更新
    │
    ├── c. 排空实例池
    │   ├── 标记状态为 "reloading"
    │   ├── 新请求等待或返回 503
    │   ├── 等待正在执行的推理完成
    │   └── 超时 (30s) → 放弃更新，恢复 "ready"
    │
    ├── d. 逐个实例执行 reload
    │   ├── 调用 ai_plugin_reload(handle, new_model_dir)
    │   ├── 成功 → 继续下一个
    │   └── 失败 → 对已 reload 的实例回滚，恢复旧模型
    │
    ├── e. 预热
    │   └── 对每个实例调用 ai_plugin_warmup(handle)
    │
    ├── f. 恢复服务
    │   ├── 标记状态为 "ready"
    │   └── 保存回滚信息
    │
    └── g. 记录日志
        └── [RELOAD] face_detect model updated: v2 -> v3 (cost: 2.5s)
```

## 10.4 SO 插件更新完整流程

```
管理员操作:
│
├── 1. 将新 SO 上传到宿主机
│   └── 放入 /opt/ai_platform/plugins/
│   └── 备份旧版本到 .versions/ 目录
│
├── 2. 触发 reload
│   └── POST /api/v1/admin/reload
│       { "capability_id": "face_detect", "type": "plugin" }
│
└── 3. 平台自动执行:
    │
    ├── a. 定位新 SO
    │   └── /opt/ai_platform/plugins/libcap_face_detect.so
    │
    ├── b. 预校验
    │   ├── 检查 SO 文件可读
    │   ├── 尝试 dlopen (不绑定)
    │   ├── 检查必需符号是否存在
    │   ├── 获取插件 API 版本
    │   └── 任一失败 → 返回错误
    │
    ├── c. 排空实例池
    │   └── (同模型更新)
    │
    ├── d. 销毁旧实例
    │   └── 对每个 handle 调用 old_plugin->destroy(handle)
    │
    ├── e. 卸载旧 SO
    │   └── dlclose(old_dl_handle)
    │
    ├── f. 加载新 SO
    │   ├── dlopen(new_so_path)
    │   ├── dlsym 绑定所有接口
    │   └── 失败 → 尝试重新加载旧 SO 恢复
    │
    ├── g. 创建新实例
    │   ├── 对每个池位调用 new_plugin->init(params, &handle)
    │   └── 失败 → 回滚到旧 SO + 旧实例
    │
    ├── h. 填充实例池
    │   └── pool->replace_all(new_handles)
    │
    ├── i. 预热 + 恢复服务
    │
    └── j. 更新 .active 记录，记录日志
```

## 10.5 License 更新流程

```
方式 A: 自动检测
│
├── 后台监控线程每小时检查
├── 检测 license.dat 文件修改时间变化
├── 读取新 License → 完整校验
├── 校验通过 → 原子更新内存缓存
└── 校验失败 → 保留旧 License 继续使用，记录告警

方式 B: 主动触发
│
├── POST /api/v1/admin/reload { "type": "license" }
├── 立即读取 License 文件
├── 完整校验
├── 校验通过 → 更新缓存
└── 校验失败 → 返回错误
```

## 10.6 回滚机制

### 10.6.1 模型回滚

```bash
# 方式 1: 手动回滚软链接 + 触发 reload
cd /opt/ai_platform/models/face_detect
ln -sfn v2 current
curl -X POST http://localhost:8080/api/v1/admin/reload \
  -H "Content-Type: application/json" \
  -d '{"capability_id": "face_detect", "type": "model"}'

# 方式 2: 使用 rollback API (自动切回上一版本)
curl -X POST http://localhost:8080/api/v1/admin/rollback \
  -H "Content-Type: application/json" \
  -d '{"capability_id": "face_detect"}'
```

### 10.6.2 SO 回滚

```bash
# 从 .versions/ 恢复旧 SO
cp /opt/ai_platform/plugins/.versions/libcap_face_detect.so.1.1.0 \
   /opt/ai_platform/plugins/libcap_face_detect.so

# 触发 reload
curl -X POST http://localhost:8080/api/v1/admin/reload \
  -H "Content-Type: application/json" \
  -d '{"capability_id": "face_detect", "type": "plugin"}'
```

### 10.6.3 自动回滚

任何更新失败时，系统自动回滚：

```
更新失败自动回滚策略:
│
├── 模型 reload 失败:
│   └── 对已 reload 的实例调用 reload(old_model_dir)
│   └── 恢复旧模型，标记 "ready"
│
├── 新 SO 加载失败:
│   └── 重新 dlopen 旧 SO
│   └── 用旧 SO 创建新实例
│   └── 恢复服务
│
└── 新实例创建失败:
    └── 销毁已创建的新实例
    └── 用旧 SO + 旧模型重建实例
    └── 恢复服务
```

## 10.7 更新脚本工具

提供宿主机端的更新辅助脚本：

```bash
#!/bin/bash
# update_tool.sh — 宿主机端更新辅助工具

PLATFORM_URL="http://localhost:8080"
BASE_DIR="/opt/ai_platform"

case "$1" in
    update-model)
        CAPABILITY=$2
        VERSION=$3
        MODEL_ARCHIVE=$4
        
        echo "Updating model: $CAPABILITY to $VERSION"
        
        # 1. 解压模型包
        TARGET_DIR="$BASE_DIR/models/$CAPABILITY/$VERSION"
        mkdir -p "$TARGET_DIR"
        tar -xzf "$MODEL_ARCHIVE" -C "$TARGET_DIR"
        
        # 2. 更新软链接
        cd "$BASE_DIR/models/$CAPABILITY"
        ln -sfn "$VERSION" current
        
        # 3. 触发 reload
        curl -s -X POST "$PLATFORM_URL/api/v1/admin/reload" \
            -H "Content-Type: application/json" \
            -H "X-Admin-Token: $ADMIN_TOKEN" \
            -d "{\"capability_id\": \"$CAPABILITY\", \"type\": \"model\"}"
        
        echo "Done."
        ;;
        
    update-plugin)
        CAPABILITY=$2
        SO_FILE=$3
        
        echo "Updating plugin: $CAPABILITY"
        
        # 1. 备份旧版本
        OLD_SO="$BASE_DIR/plugins/libcap_${CAPABILITY}.so"
        if [ -f "$OLD_SO" ]; then
            VERSION=$(date +%Y%m%d%H%M%S)
            cp "$OLD_SO" "$BASE_DIR/plugins/.versions/libcap_${CAPABILITY}.so.$VERSION"
        fi
        
        # 2. 复制新 SO
        cp "$SO_FILE" "$OLD_SO"
        
        # 3. 触发 reload
        curl -s -X POST "$PLATFORM_URL/api/v1/admin/reload" \
            -H "Content-Type: application/json" \
            -H "X-Admin-Token: $ADMIN_TOKEN" \
            -d "{\"capability_id\": \"$CAPABILITY\", \"type\": \"plugin\"}"
        
        echo "Done."
        ;;
        
    update-license)
        LICENSE_FILE=$2
        
        echo "Updating license"
        
        # 1. 备份旧 License
        if [ -f "$BASE_DIR/license/license.dat" ]; then
            cp "$BASE_DIR/license/license.dat" \
               "$BASE_DIR/license/.backup/license.dat.$(date +%Y%m%d)"
        fi
        
        # 2. 复制新 License
        cp "$LICENSE_FILE" "$BASE_DIR/license/license.dat"
        
        # 3. 触发检查
        curl -s -X POST "$PLATFORM_URL/api/v1/admin/reload" \
            -H "Content-Type: application/json" \
            -H "X-Admin-Token: $ADMIN_TOKEN" \
            -d '{"type": "license"}'
        
        echo "Done."
        ;;
        
    rollback)
        CAPABILITY=$2
        curl -s -X POST "$PLATFORM_URL/api/v1/admin/rollback" \
            -H "Content-Type: application/json" \
            -H "X-Admin-Token: $ADMIN_TOKEN" \
            -d "{\"capability_id\": \"$CAPABILITY\"}"
        ;;
        
    status)
        curl -s "$PLATFORM_URL/api/v1/capabilities" | python3 -m json.tool
        ;;
        
    *)
        echo "Usage: $0 {update-model|update-plugin|update-license|rollback|status} [args...]"
        ;;
esac
```

## 10.8 更新安全保障

| 保障措施 | 说明 |
|---------|------|
| **Checksum 校验** | 模型更新前校验 SHA256 |
| **API 版本兼容** | 新 SO/模型必须满足 API 版本约束 |
| **Drain 机制** | 更新前等待进行中的推理完成 |
| **原子切换** | 实例池整体替换，不存在半更新状态 |
| **自动回滚** | 任何步骤失败自动恢复 |
| **审计日志** | 所有更新操作记录日志 |
| **Admin Token** | 更新接口需要管理令牌认证 |

## 10.9 SDK 交付包更新说明

单能力交付包更新分为三类：

- **Linux SO/JNI 包更新**：替换 `libcap_xxx.so`、`libai_jni_xxx.so` 和模型目录
- **Windows DLL 包更新**：替换 `cap_xxx.dll`、`cap_xxx.lib` 和模型目录
- **License 更新**：替换本地授权文件并重新初始化 SDK

对于 SDK 形态，建议提供独立的 `sdk_update_tool` 完成版本校验、备份和回滚。
