# 01 — 项目概述与目标

## 1.1 项目背景

本项目旨在构建一个**可交付的 AI 能力运行平台**（AI Capability Platform），以统一的 Docker 容器形态，向客户交付多种专用 AI 能力模块。平台不是简单的模型服务，而是一套完整的"AI 运行平台"，包含推理引擎、能力插件、授权控制、更新回滚、测试界面等完整生态。

同时，平台还需要支持**多种交付形态并行演进**：

1. **统一 Docker 平台交付**：面向完整 AI 能力平台场景，包含 HTTP 服务、Runtime、插件、模型、授权。
2. **单能力 Linux SO + 模型交付**：面向第三方本地集成调用，不包含 Web 服务。
3. **单能力 JNI + SO + 模型交付**：面向 Java 系统集成，不包含 Web 服务。
4. **单能力 Windows DLL + 模型交付**：面向 Windows 客户端/服务端程序集成。
5. **多架构平台扩展交付**：后续支持 ARM Linux、国产化平台等环境。

## 1.2 核心设计理念

| 理念 | 说明 |
|------|------|
| **插件化** | 每个 AI 能力独立为一个 C++ SO 插件，互不影响 |
| **可扩展能力平台** | 后续新增 AI 能力时，通过新增插件、模型包、配置即可接入，不影响现有能力 |
| **开箱即用** | Docker 镜像自带全部程序和模型，启动即可运行 |
| **现场可更新** | 通过宿主机挂载目录实现 SO/模型/License 热更新，无需重打镜像 |
| **安全可控** | 离线授权、机器绑定、试用期控制、双层校验 |
| **并发安全** | 能力实例池模式，支持高并发推理 |
| **CUDA优先，CPU兜底** | 优先使用 GPU 加速，无 GPU 时自动降级为 CPU 推理 |
| **多交付形态统一内核** | Docker 服务、JNI、Linux SO、Windows DLL 共用统一推理内核与插件规范 |
| **跨平台演进** | 从 Linux x86_64 起步，设计阶段预留 Windows、ARM 等平台适配空间 |

## 1.6 技术栈选型

| 层级 | 技术选型 | 说明 |
|------|---------|------|
| **HTTP 服务** | C++ (cpp-httplib) | 轻量高性能 HTTP 服务，无外部依赖 |
| **JSON 处理** | nlohmann/json | C++ 标准 JSON 库 |
| **推理框架** | ONNX Runtime + CUDA EP | 统一推理后端，支持 CUDA/CPU 自动切换 |
| **图像处理** | OpenCV 4.x | 图像预处理、解码 |
| **构建系统** | CMake 3.20+ | 统一构建，支持交叉编译 |
| **容器** | Docker + NVIDIA Container Toolkit | CUDA 支持 |
| **基础镜像** | nvidia/cuda:12.2-cudnn8-runtime-ubuntu22.04 | CUDA 12.2 + cuDNN 8 |
| **前端测试页** | React + Ant Design | 现代化测试 Web 界面 |
| **授权加密** | OpenSSL (RSA/AES) | License 签名与验证 |
| **日志** | spdlog | 高性能 C++ 日志库 |
| **配置** | YAML (yaml-cpp) | 配置文件格式 |
| **JNI 桥接** | JNI + C++ Wrapper | 支持 Java 集成 |
| **Windows 交付** | DLL + DEF/Lib 导出 | 支持 Windows 单能力交付 |

## 1.7 设计约束

1. **全离线运行**：交付环境无外网，所有依赖必须内置
2. **单容器部署**：所有能力运行在同一个 Docker 容器中
3. **C++ 实现**：推理插件和主服务均使用 C++ 实现
4. **标准 C ABI**：插件接口必须使用 C ABI，确保二进制兼容
5. **无状态推理**：每次推理调用独立，不依赖上下文状态
6. **Linux x86_64 优先**：首期主交付平台为 Linux x86_64
7. **跨平台预留**：设计需支持后续扩展到 Windows x86_64、Linux ARM64 等平台
8. **媒体输入可扩展**：输入不局限于图片，需要支持视频文件、视频帧序列等媒体输入
9. **端口规划统一**：所有 Docker 交付容器对宿主机映射端口统一从 `26000` 开始顺延，`26000` 之前端口不使用
