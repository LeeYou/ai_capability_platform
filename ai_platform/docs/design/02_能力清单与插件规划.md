## 2.1.1 扩展原则

 为支持后续持续新增 AI 能力，能力规划遵循以下原则：

 1. **新增能力不改 Runtime 核心接口**：优先通过新增插件、模型包、配置和前端页面接入。
 2. **新增能力不影响既有能力**：能力之间通过插件边界隔离，避免共享可变实现。
 3. **输入类型可扩展**：除图片外，可支持视频文件、视频帧序列、结构化文本等输入。
 4. **交付形态复用**：新增能力默认同时具备 Docker 平台版、Linux SO 版、JNI 版、Windows DLL 版的可交付能力。
 5. **多平台编译预留**：新能力开发时需避免绑定特定平台 API。

## 2.3 各能力详细定义

### C01 — 人脸检测 (face_detect)

| 项 | 值 |
|----|-----|
| **功能** | 在图像中检测所有人脸位置 |
| **输入** | 单张图像 (JPEG/PNG/BMP, Base64 编码) |
| **输出** | 人脸边界框数组 `[{x, y, w, h, confidence, landmarks_5}]` |
| **模型** | RetinaFace / SCRFD (ONNX) |
| **预处理** | Resize + Normalize + HWC→CHW |
| **后处理** | NMS + 阈值过滤 |
| **依赖能力** | 无 (基础能力，被多个能力依赖) |

### C02 — 人脸识别 (face_recognize)

| 项 | 值 |
|----|-----|
| **功能** | 比对两张人脸的相似度 |
| **输入** | 两张人脸图像 (经人脸检测裁剪后的对齐图) |
| **输出** | `{similarity: float, is_same: bool, threshold: float}` |
| **模型** | ArcFace / CosFace (ONNX) |
| **预处理** | 人脸对齐 + Resize 112x112 + Normalize |
| **后处理** | 特征提取 → 余弦相似度计算 |
| **依赖能力** | C01 (人脸检测提供定位) |

### C03 — 指令活体检测 (liveness_action)

| 项 | 值 |
|----|-----|
| **功能** | 通过指定动作（眨眼、张嘴、摇头、点头）判断活体 |
| **输入** | 视频帧序列或多张图像 + 指令类型 |
| **输出** | `{is_live: bool, action_results: [{action, passed}], score: float}` |
| **模型** | 动作分类模型 (ONNX) |
| **依赖能力** | C01 (人脸检测) |

### C04 — 静默活体检测 (liveness_silent)

| 项 | 值 |
|----|-----|
| **功能** | 单张图像判断是否为活体（防照片/屏幕攻击） |
| **输入** | 单张图像 |
| **输出** | `{is_live: bool, score: float, threshold: float}` |
| **模型** | FAS 模型 (ONNX) |
| **依赖能力** | C01 (人脸检测) |

### C05 — 人脸属性检测 (face_attribute)

| 项 | 值 |
|----|-----|
| **功能** | 检测人脸属性：是否戴眼镜、戴帽子、戴口罩、歪头角度等 |
| **输入** | 单张人脸图像 |
| **输出** | `{glasses: bool, hat: bool, mask: bool, head_pose: {yaw, pitch, roll}, age_range, gender}` |
| **模型** | 多任务属性分类模型 (ONNX) |
| **依赖能力** | C01 (人脸检测) |

### C06 — 身份证检测 (idcard_detect)

| 项 | 值 |
|----|-----|
| **功能** | 在图像中检测并定位身份证区域 |
| **输入** | 单张图像 |
| **输出** | `{boxes: [{x, y, w, h, confidence, side: "front"|"back"}]}` |
| **模型** | 目标检测模型 YOLOv8/YOLO类 (ONNX) |
| **依赖能力** | 无 |

### C07 — 证件类型识别 (doc_classify)

| 项 | 值 |
|----|-----|
| **功能** | 识别证件类型 |
| **支持类型** | 二代身份证(人像面/国徽面)、临时身份证、港澳台居住证、户口本、中国护照、国际护照、军官证 |
| **输入** | 单张图像 |
| **输出** | `{doc_type: string, doc_type_id: int, confidence: float}` |
| **模型** | 分类模型 (ONNX) |
| **依赖能力** | 无 |

### C08 — 手写签字识别 (handwriting_recognize)

| 项 | 值 |
|----|-----|
| **功能** | 检测并识别手写签字内容 |
| **输入** | 单张图像 |
| **输出** | `{regions: [{box, text, confidence}]}` |
| **模型** | 检测模型 + 识别模型 (ONNX) |
| **依赖能力** | 无 |

### C09 — 营业执照识别 (business_license_ocr)

### C10 — 印章检测 (seal_detect)

| **模型** | 目标检测模型 (ONNX) |
| **依赖能力** | 无 |

### C11 — 印章识别 (seal_recognize)

| **输入** | 单张印章图像 |

| **输入** | 单张图像、视频帧序列或一段小视频 |

| **依赖能力** | C01 (人脸检测) |

|----|-----|
| **功能** | 通用文字检测与识别 |

| **模型** | 文字检测(DBNet) + 文字识别(CRNN) (ONNX) |
| **依赖能力** | 无 (基础能力，被多个 OCR 类能力依赖) |

## 2.5 插件共享策略

为避免重复加载和资源浪费，以下能力可共享底层模型：

| 共享组 | 共享模型 | 使用能力 |
|--------|---------|---------|
| **人脸检测模型** | RetinaFace/SCRFD | C01, C02(前置), C03(前置), C04(前置), C05(前置), C15(前置), C16(前置) |
| **OCR 基础模型** | DBNet + CRNN | C17, C08, C09, C12, C13, C14 |

**共享实现方案**：
- 每个 SO 插件**内部自包含**所需模型加载逻辑
- Runtime 层通过**模型缓存池**实现跨插件的模型共享
- 插件通过 manifest 声明所依赖的 `shared_model_id`
- Runtime 在加载插件前，先确保共享模型已加载，并通过初始化参数将共享模型 handle 传入插件

## 2.6 首期实施范围

**首期 (Phase 1)** — 核心能力 + 框架搭建：
- 平台框架全部完成 (HTTP 服务 + Runtime + 插件加载 + 授权)
- P0 能力：C01, C02, C03, C04, C06
- P1 能力：C05, C07, C15, C17

 **二期 (Phase 2)** — 扩展能力：
 - P1 能力：C10, C11, C16
 - P2 能力：C08, C09, C12, C13, C14

## 2.7 新增能力接入规范

 后续新增能力时，至少需要补齐以下内容：

 - **能力插件**：新增 `src/plugins/<capability_id>/`
 - **模型包**：新增 `models/<capability_id>/`
 - **能力配置**：新增 `config/capabilities/<capability_id>.yaml`
 - **测试页面**：新增 `web/src/pages/test/<CapabilityName>Test.tsx`
 - **授权能力项**：在 License 的 `capabilities.allowed` 中增加能力标识
 - **交付产物**：评估是否需要同步输出 JNI 版、Windows DLL 版
