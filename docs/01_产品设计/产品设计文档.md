# ai_capability_platform 产品设计文档

## 1. 文档目标

定义 ai_capability_platform 的产品定位、目标用户、业务范围、核心能力、交付物与关键运营约束，为后续架构设计、模块设计和实施计划提供统一基线。

## 2. 产品定位

ai_capability_platform 是一套工业级 AI 通用能力平台，覆盖从样本标记、模型训练、模型测试、授权管理、推理库构建到生产交付的完整流水线，并支持后续模型微调训练迭代、交付更新和现场回滚。

平台服务于“研发构建”和“客户交付”双场景：

1. 对内形成统一 AI 能力生产线。
2. 对外形成可授权、可更新、可审计、可回滚的交付平台。

## 3. 产品愿景

1. 统一 AI 能力从研发到生产的生命周期管理。
2. 降低新增 AI 能力的接入成本和交付成本。
3. 提供可扩展、可插件化、可审计、可并发的工业级推理运行体系。
4. 通过授权、版本、回滚和挂载更新机制支撑现场稳定交付。

## 4. 目标用户

### 4.1 内部用户

1. 数据标注工程师
2. 算法工程师
3. 测试工程师
4. 交付工程师
5. 运维工程师
6. 产品与项目管理人员

### 4.2 外部用户

1. 企业客户技术团队
2. 第三方系统集成商
3. 需要 SDK/JNI 调用能力的合作方

## 5. 产品边界

### 5.1 平台纳入范围

1. 数据集目录接入与样本标记管理
2. AI 能力训练任务管理与模型产出管理
3. AI 模型单接口测试、批量测试、测试报告管理
4. 客户、公私钥、授权文件与授权策略管理
5. AI 能力推理库构建与多平台产物组织
6. Docker 生产镜像交付与单机推理库交付
7. 运行时能力发现、模型装载、授权校验、热重载与回滚

### 5.2 平台暂不纳入范围

1. 分布式训练集群调度系统
2. 公有云托管式多租户 SaaS 计费系统
3. 自动化数据采集系统

## 6. 核心业务流程

1. 创建或注册 AI 能力
2. 绑定宿主机数据集目录
3. 进行样本标记与数据版本管理
4. 发起训练任务并产出模型
5. 进行模型测试并生成测试报告
6. 生成客户授权文件
7. 选择能力、模型、授权执行推理库构建
8. 生成生产交付物并部署到客户环境
9. 通过宿主机挂载目录进行模型、SO、license 增量更新
10. 执行 reload/rollback 完成现场更新与回滚

## 7. 产品子系统定义

### 7.1 ai-train

职责：样本标记、训练管理、模型管理、AI 能力元数据服务。

### 7.2 ai-test

职责：模型测试、批量测试、报告生成、测试结果归档。

### 7.3 ai-license-mgr

职责：密钥对管理、客户管理、授权文件管理、授权策略管理。

### 7.4 ai-builder

职责：能力推理库编译、交付构建、JNI 可选构建、多平台产物组织。

### 7.5 ai-prod

职责：统一生产镜像、HTTP REST 服务、runtime、动态插件加载、现场更新。

### 7.6 单机交付 SDK

职责：面向第三方交付推理库、头文件、模型包、JNI 封装与说明文档。

## 8. 核心产品能力

### 8.1 AI 能力注册与动态扩展

1. 新增能力时同步补齐训练、测试、推理、构建模板。
2. 能力元数据统一注册，供 train/test/builder/prod 查询。
3. 支持后续动态新增能力而不破坏既有能力。

### 8.2 数据与模型资产管理

1. 宿主机固定目录接入
2. 数据集与能力绑定
3. 模型版本化管理
4. 测试报告与构建产物可追溯

### 8.3 交付与更新能力

1. Docker 交付优先
2. 单机 SDK 交付补充
3. 宿主机挂载目录优先加载
4. 支持 license、模型、SO 三类独立更新
5. 支持 reload 与回滚

### 8.4 工业级运行能力

1. 高并发推理
2. GPU 优先、CPU 自动回退
3. 统一错误码与日志
4. 运行状态、能力列表、授权状态可观测

## 9. 非功能需求

### 9.1 性能

1. 生产接口支持并发调用。
2. Runtime 采用能力实例池，不允许单全局锁串行化推理。
3. 模型装载与重载需具备可控时延。

### 9.2 稳定性

1. 核心更新操作支持原子切换。
2. 支持健康检查、版本检查和回滚。
3. 插件故障隔离，避免单能力异常拖垮全系统。

### 9.3 安全

1. 授权采用数字签名机制。
2. 生产服务必须校验授权状态。
3. 文件导入、构建、测试接口需限制输入类型、大小与路径访问。

### 9.4 可维护性

1. 文档先行
2. 模块边界清晰
3. 统一规范
4. 支持增量开发与迭代跟踪

## 10. 交付物定义

默认 Docker 模式交付物：

1. 统一交付镜像
2. 主 Web/API 服务
3. 通用推理运行时
4. 各 AI 能力插件 SO
5. 模型包
6. 授权文件与授权更新工具
7. 宿主机挂载目录模板
8. API 文档、更新手册、验收手册

补充单机模式交付物：

1. 推理库
2. 头文件
3. 模型包
4. license 文件
5. JNI 封装与接入说明

## 11. 关键约束

1. CUDA 固定为 11.8。
2. 所有文件统一 UTF-8。
3. 注释与 git 提交说明统一中文。
4. 宿主机映射端口从 26000 起连续规划。
5. C++ 采用 Google 风格，但禁用成员变量尾下划线命名。
6. npm 下载优先使用国内源。
