# 新增能力接入指南

## 1. 概述

本文档描述如何在 AI 能力平台中接入一个新的 AI 能力（capability）。从数据标注到模型训练、插件构建、测试验收和 SDK 交付，平台提供全链路模板化脚手架，可在无需重复设计的情况下快速完成新能力接入。

支持的任务类型（task_type）：
- `classification`：图像/文本分类
- `detection`：目标检测
- `ocr`：文字识别
- `structured_extraction`：结构化信息抽取

## 2. 快速开始

使用接入脚手架一键生成全链路接入物料：

```bash
cd apps/shared/scripts
python onboard_capability.py \
  --capability_name my_capability \
  --task_type classification \
  --output_dir /tmp/my_capability
```

输出文件：`/tmp/my_capability/capability_onboarding_guide.json`

该文件包含：
- 标注 schema 模板（annotation_schema）
- 训练任务模板（training_template）
- 构建任务模板（builder_template）
- 回归测试模板（test_template）
- 运行时接入要求（prod_template）
- 接入检查项清单（onboarding_checklist，共 12 步）

## 3. 接入步骤

### 步骤 1–4：ai-train 训练链路

1. **定义标注 schema**：根据 task_type 选择对应的标注 schema，字段定义参考 `annotation_schema.required_fields`。
2. **准备数据集**：将标注结果存入 `datasets/<capability_name>/` 目录，格式与 `dataset_format` 一致。
3. **创建训练任务**：调用 `POST /api/v1/training/tasks`，参数包含 `capability_name`、`task_type`、`dataset_path`。
4. **导出模型包**：训练完成后调用导出接口，得到包含 `manifest.json`、`weights.bin`、`metrics.json` 的标准模型包。

### 步骤 5–7：ai-builder 构建链路

5. **创建构建任务**：调用 `POST /api/v1/build/tasks`，上传模型包路径（`source_model_artifact_path`）。
6. **等待构建完成**：构建产物包含 C++ 插件动态库、`delivery_package/`、`package_manifest.json`。
7. **校验可装载性**：检查 `pre_delivery_validation.json` 中 `overall_status = "passed"`，确认插件、模型包、license 兼容性通过。

### 步骤 8–9：ai-test 测试链路

8. **创建模板化回归任务**：

```python
from app.services.test_service import create_template_regression_task

result = create_template_regression_task(
    session=session,
    model_catalog_snapshot_path=...,
    ai_train_api_base_url=...,
    datasets_root=...,
    test_reports_root=...,
    capability_name="my_capability",
    model_version="v1.0.0",
    sample_input_path="my_capability/sample.jpg",
)
```

9. **确认证据链**：在测试报告 summary 中确认 `evidence_chain` 包含 `source_train_task_id`、`manifest_checksum`、`builder_task_id`。

### 步骤 10–11：ai-prod 运行时接入

10. **热加载新能力**：调用 `POST /api/v1/reload`，ai-prod 会执行 `admission_checklist` 校验（ABI 符号、manifest schema、license 兼容性）。
11. **推理验收**：调用 `POST /api/v1/infer`，比对实际输出格式与 `prod_template.expected_infer_output` 一致。

### 步骤 12：ai-sdk 交付

12. **生成 SDK 包**：调用 ai-sdk 交付接口，指定 `delivery_package` 路径；校验产物中的 `delivery_summary.json` 确认 `status = "ready"`。

## 4. 各模块契约对照表

| 字段 | ai-train | ai-builder | ai-test | ai-prod |
|------|----------|------------|---------|---------|
| capability_name | 训练任务字段 | 构建目标字段 | 测试任务字段 | 能力注册字段 |
| task_type | 标注 schema 选择 | 插件模板选择 | 输出 schema 选择 | manifest 字段 |
| source_train_task_id | 训练任务 ID | provenance 来源 | evidence_chain 字段 | — |
| manifest.json | 导出产物 | 强消费字段 | 装载 manifest | admission 校验 |
| license | — | 交付前校验 | evidence_chain 字段 | admission 门禁 |

## 5. 典型错误与排查

| 现象 | 可能原因 | 排查点 |
|------|----------|--------|
| builder 校验失败 | 模型包缺少 manifest.json | 检查训练导出是否成功 |
| admission_gate_failures | ABI 符号未找到 | 确认插件 `capability_name_plugin_create` 入口符号 |
| evidence_chain 为 None | 模型 manifest 缺少 task_type | 检查 manifest.json 中 task_type 字段 |
| 推理输出格式不符 | task_type 不匹配 | 确认 manifest.json 与训练任务 task_type 一致 |
