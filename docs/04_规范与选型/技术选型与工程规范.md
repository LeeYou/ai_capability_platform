# 技术选型与工程规范

## 1. 技术选型总原则

1. 优先选择主流、成熟、安全、长期维护的技术栈。
2. 管理面与运行面技术解耦。
3. 训练、测试、交付共享统一元数据与协议规范。
4. 严格围绕 CUDA 11.8 做兼容性控制。

## 2. 技术选型

### 2.1 管理系统

1. 前端：React + TypeScript + Vite
2. 后端：Python 3.11 + FastAPI
3. ORM：SQLModel 或 SQLAlchemy
4. 数据库：SQLite（首期），预留后续升级 PostgreSQL

### 2.2 AI 相关

1. 训练框架：PyTorch
2. 测试推理：Python + ONNX Runtime
3. 交付推理：C++ + ONNX Runtime
4. 构建系统：CMake

### 2.3 生产服务

1. Web/API：FastAPI
2. Runtime：C++ 动态库
3. 容器化：Docker
4. 多架构镜像：amd64/arm64

## 3. CUDA 与依赖规范

1. 全平台统一使用 CUDA 11.8。
2. 所有 GPU 相关依赖版本必须明确标注与 CUDA 11.8 兼容。
3. 不允许引入其他 CUDA 主版本依赖。
4. GPU 不可用时必须自动切换 CPU。

## 4. Docker 规范

1. Dockerfile 必须区分稳定层与频繁变更层。
2. 安装依赖优先使用缓存友好的层次结构。
3. npm 源优先配置国内源，如清华源。
4. 容器端口从 26000 起规划：
   - ai-train：26000
   - ai-test：26001
   - ai-license-mgr：26002
   - ai-builder：26003
   - ai-prod：26004

## 5. 宿主机挂载规范

根目录：`/data/ai_capability_platform/`

1. `data/`：持久化数据库、元数据、测试报告
2. `datasets/`：训练与测试数据集
3. `models/`：部署模型包
4. `license/`：授权文件
5. `libs/`：交付推理库
6. `configs/`：运行配置
7. `logs/`：日志
8. `exports/`：导出文件

## 6. C++ 编码规范

1. 采用 Google 编码风格。
2. 严禁使用成员变量尾下划线命名方式。
3. 统一使用清晰的语义化命名。
4. 严格区分接口头文件与实现文件。
5. 显式声明线程安全边界和内存所有权。

## 7. Python 编码规范

1. 统一使用 Python 3.11。
2. 强制类型标注。
3. API、任务、模型逻辑分层。
4. 路径访问使用白名单目录与安全拼接。

## 8. 前端规范

1. TypeScript 严格模式。
2. 页面按子系统分域组织。
3. API 类型定义集中管理。
4. 管理页面统一展示公司信息与版本信息。

## 9. API 设计规范

1. REST 风格统一。
2. 统一版本前缀 `/api/v1/`。
3. 统一错误码、错误消息、request_id。
4. 输入支持文件类统一抽象，涵盖图片、视频、PDF 等。

## 10. 模型包规范

每个模型包至少包含：

1. 模型文件
2. manifest
3. 预处理配置
4. 阈值配置
5. 标签定义
6. checksum

## 11. License 规范

license 内容至少包含：

1. customer_id
2. capability_scope
3. hardware_fingerprint
4. start_at_cst
5. expire_at_cst
6. version_constraints
7. signature

## 12. 文档规范

1. 所有文件统一 UTF-8。
2. 文档、注释、提交说明统一中文。
3. 设计文档先于实现。
4. 变更后需同步更新计划与评审文档。

## 13. 安全规范

1. 禁止硬编码密钥。
2. 禁止任意路径读写。
3. 禁止任意命令拼接执行。
4. 上传文件需校验类型、大小、存储位置。
5. 构建与生产接口必须记录审计日志。
