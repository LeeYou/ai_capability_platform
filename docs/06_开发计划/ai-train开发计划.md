# ai-train 开发计划

## 1. 模块目标

持续完善内部研发侧的样本标注、训练管理、模型管理与能力查询能力，并提升 UI 体验与模型包标准化程度，为交付链路提供稳定输入。

## 3. 进度维护要求

每次开发前后更新状态、风险、阶段小结，并同步对照 `docs/05_评审/代码逻辑自洽整改清单.md` 中 RT-01 ~ RT-05。

## 4. 当前进度更新

### 4.1 已完成

1. 已完成 ai-train 基础版前后端骨架、数据集扫描、能力注册与元数据持久化。
2. 已完成标注任务、训练任务、模型产物、训练工作区准备与基础前端管理台。
3. 已完成基础版 Docker、测试与回归校验。

### 4.2 进行中

1. T1-T16 已完成，当前模块能力已具备真实标注、训练执行、模型资产与模型包契约基础。
2. 下一轮将转入 Web 产品化收口，重点不再是补 API，而是把现有能力重构为真正高效的研发工作台。
3. T17 目标：重构标注工作台为“样本列表 + 主画布 + 属性/质检侧栏”三栏布局，统一 detection / OCR / classification / structured_extraction 的操作体验。
4. T18 目标：重构训练工作台，补齐任务阶段状态条、日志检索、指标卡片、失败重试与结果摘要联动。
5. T19 目标：重构模型资产页，突出模型卡片、manifest 摘要、版本对比与“送测”主操作。
6. T20 目标：补齐首页待办、最近任务、异常提醒，以及面向 ai-test 的跨模块跳转入口。

### 4.3 未完成

1. T17：标注工作台布局重构与统一画布交互收口。
2. T18：训练工作台日志 / 指标 / 阶段状态专业化重构。
3. T19：模型资产页与“送测”主流程收口。
4. T20：跨模块对象跳转与首页待办视图收口。

### 4.4 阶段小结

ai-train 当前功能基础已较完整，下一轮重点是把“能做”收口为“好用”。T17-T20 将围绕标注台三栏布局、训练日志与阶段态工作台、模型资产卡片化与送测主流程、首页待办与跨模块跳转展开，目标是让 ai-train 成为整条产品链中最成熟的起点工作台，而不是功能集合页。
