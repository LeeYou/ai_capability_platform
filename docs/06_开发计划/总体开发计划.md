# 总体开发计划

## 1. 计划目标

按照“上层平台完整、运行底座扎实”的目标分阶段推进平台建设：保留当前平台在内部研发测试流程上的优势，重点吸收 `ai_platform` 在 Runtime 内核、交付目录与验收体系、生产侧 License / 热更新 / 回滚机制方面的成熟设计。

## 2. 计划状态说明

- 状态值：未开始 / 进行中 / 已完成 / 阻塞
- 当前版本状态：进行中（R2/R4/R5 持续推进，R3/R6 已完成，当前已完成 ai-prod P28、ai-test TT11、ai-license-mgr L8/L9/L10 收口）

## 4. 跨模块公共工作项

1. 建立 mono-repo 目录结构
2. 建立前后端基础工程
3. 建立共享元数据协议
4. 建立错误码、manifest、license schema
5. 建立 Docker 基础镜像与挂载目录模板
6. 建立 CI、质量检查与文档更新流程
7. 建立标准 `delivery_package/` 目录规范
8. 建立生产运行底座与内部测试外壳的分层边界

## 5. 进度跟踪要求

1. 每个模块实现前先核对设计文档与模块计划。
2. 实现前更新模块计划实际状态。
3. 实现完成后更新模块计划、总体计划与阶段小结。
4. 提交代码时使用中文提交说明。
5. 每轮实现完成后必须比对设计文档、开发计划与实际代码，确认未跑偏。

## 6. 当前里程碑结论

1. 基础版六个业务模块、单机交付 SDK、共享 schema、Docker 基础镜像、compose 编排与 CI 已完成。
2. 已完成与 `ai_platform` 的深度对比评估，并明确后续目标。
3. 当前已完成设计文档与开发计划的融合刷新，下一阶段进入运行底座与交付体系实现阶段。

### 7.2 进行中

3. SDK、tools、docs、mount_template 与摘要 schema 仍可继续按最终交付目标细化。

### 7.4 阶段小结

当前平台已具备内部研发测试流程的基础版闭环能力。随着 ai-prod 完成 P9-P28、ai-builder 完成 B9/B10/B11、ai-test 完成 TT9/TT10/TT11、ai-license-mgr 完成 L8/L9/L10，平台一侧已经具备交付主入口、能力目录管理、轻量实例池状态维护、交付级验收脚本、标准 `delivery_package/` 目录输出、ai-prod 生产镜像构建上下文 tarball、挂载模板、验收/运维工具、部署文档，以及验收清单、版本清单、交付摘要等最终收口物料；同时 ai-prod 的 infer 热路径已在 snapshot 可用时由 C++ 直接完成请求解析、license quick check、设备选择、实例池借还、真实插件动态加载执行、结果生成与基础日志审计，启动阶段的 bootstrap 首次装载与 reload/rollback 管理链路也已由 C++ 直接完成资源扫描、revision/operation SQLite 持久化、runtime snapshot 初始/重写与 catalog/pool 刷新，并进一步补齐 runtime 显式状态机、请求级 in-flight 跟踪、RAII 请求租约、能力级执行指标聚合、插件 `warmup` / `health_check` 生命周期钩子、统一输入 `payload codec`、切换互斥保护、基于 revision 的完整能力资源快照持久化与真实回滚恢复，以及 capability 级 `max_batch_size` / `instance_count` 元数据透传、繁忙拒绝观测、基础请求排队等待与调度观测、capability 级排队策略元数据透传；ai-test 也已新增生产镜像验收任务、性能/稳定性验收基线模型、回归脚本编排基础链路，以及“研发验收 / 交付验收”双视角报告模板，可对 ai-prod 公共入口统一编排 `acceptance_check.py` / `pressure_smoke.py` 并输出技术分析视角与交付核对视角的双套报告；ai-license-mgr 与 ai-prod 运行时的版本约束语义已完成统一，`license_tool` 已具备默认 source bundle 发布归档、README/错误码/硬件指纹说明与 delivery_package/tools 收口基础，密钥对也已补齐轮转版本、前序链路、隔离与策略迁移能力，进一步降低授权签发侧、工具交付侧与客户运行侧的落差。后续实现将继续以当前平台为主平台、以 `ai_platform` 为运行内核与交付规范参考实现，推进更完整的 Runtime 编排、SDK 示例工程/验收说明与最终现场交付闭环。
