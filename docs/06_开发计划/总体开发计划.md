# 总体开发计划

## 1. 计划目标

按照“上层平台完整、运行底座扎实”的目标分阶段推进平台建设：保留当前平台在内部研发测试流程上的优势，重点吸收 `ai_platform` 在 Runtime 内核、交付目录与验收体系、生产侧 License / 热更新 / 回滚机制方面的成熟设计。

## 2. 计划状态说明

- 状态值：未开始 / 进行中 / 已完成 / 阻塞
- 当前版本状态：进行中（基础版闭环已完成，融合增强版已启动，当前完成文档与计划刷新）

## 4. 跨模块公共工作项

1. 建立 mono-repo 目录结构
2. 建立前后端基础工程
3. 建立共享元数据协议
4. 建立错误码、manifest、license schema
5. 建立 Docker 基础镜像与挂载目录模板
6. 建立 CI、质量检查与文档更新流程
7. 建立标准 `delivery_package/` 目录规范
8. 建立生产运行底座与内部测试外壳的分层边界

## 5. 进度跟踪要求

1. 每个模块实现前先核对设计文档与模块计划。
2. 实现前更新模块计划实际状态。
3. 实现完成后更新模块计划、总体计划与阶段小结。
4. 提交代码时使用中文提交说明。
5. 每轮实现完成后必须比对设计文档、开发计划与实际代码，确认未跑偏。

## 6. 当前里程碑结论

1. 基础版六个业务模块、单机交付 SDK、共享 schema、Docker 基础镜像、compose 编排与 CI 已完成。
2. 已完成与 `ai_platform` 的深度对比评估，并明确后续目标。
3. 当前已完成设计文档与开发计划的融合刷新，下一阶段进入运行底座与交付体系实现阶段。

3. ai-prod 首轮实施已完成本地编译、CTest 与代理 smoke 验证，当前可作为后续 C++ Runtime 接入的过渡主链路骨架。
4. ai-prod 当前继续推进第二轮实施：增强 C++ HTTP 层分层结构，并补齐 rollback 管理路由兼容能力。
5. ai-prod 当前继续推进第三轮实施：让 health/capabilities/license 查询接口优先由 C++ 直读 runtime snapshot 响应，并保留自动降级转发。

10. ai-prod 当前已完成 P12：将 Python/React 测试验收外壳的内部查询接口拆分到 `/internal/*`，前端显式标记为 internal-only，且 C++ 生产主链路不再暴露 revision / operation 等内部查询接口。
11. ai-prod 当前已完成 P13：新增交付默认环境模板、公共 API 验收脚本、基础并发压测脚本与 ai-prod 运行规范文档，并在 Makefile / 运维文档中固化使用入口。
12. ai-prod 当前已完成 P9 收口：生产镜像与 compose 默认已切换到 C++ HTTP 对外主入口，Python backend 只在容器内保留为内部壳层。
13. ai-builder 当前已完成 B9：构建任务结束后会自动生成统一 `delivery_package/` 目录，将多平台 SDK 与 license 物料按稳定交付结构重组，并提供整包归档下载入口。
14. ai-builder 当前已完成 B10：在 delivery_package 中补齐 ai-prod 生产镜像构建上下文 tarball、mount_template、tools 与 docs，交付包已具备更完整的部署与运维材料。
15. ai-builder 当前已完成 B11：新增验收清单、版本清单与交付摘要生成，并将相关引用回填到 build manifest 与 delivery package manifest，交付包已具备最终收口物料。
16. ai-prod 当前已完成 P14：在 runtime snapshot 可用时，`/api/v1/infer/{capability_name}` 已由 C++ 直接完成请求解析、license quick check、设备选择、实例池借还、结果生成与基础日志审计，仅在 snapshot 不可用时回退 Python backend。
17. ai-prod 当前已完成 P15：`/api/v1/admin/reload` 与 `/api/v1/admin/rollback` 已由 C++ 直接完成资源扫描、revision/operation SQLite 持久化、runtime snapshot 重写与 catalog/pool 刷新，仅保留 Python 作为内部测试验收外壳与兼容壳层。
18. ai-prod 当前已完成 P16：C++ infer 主链路已接入真实插件动态加载、按实例槽位初始化与执行，runtime snapshot / capability catalog 已补齐 `model_root`、`binary_path` 元数据，默认由 C++ 直接调用插件返回结果，仅在 snapshot 不可用时回退 Python backend。
19. ai-prod 当前已完成 P17：当 runtime snapshot 缺失或不可用时，C++ 服务在启动阶段已可直接完成资源扫描、license quick check、bootstrap revision/operation SQLite 持久化与 runtime snapshot 初始写入，并在首启后立即刷新 catalog/pool 进入可服务状态。
20. ai-prod 当前已完成 P18：C++ 侧已新增 runtime 显式状态机，覆盖 `bootstrapping / ready / draining / transitioning / error` 状态流转，并为 reload/rollback 增加切换互斥保护；`/api/v1/admin/catalog` 现可输出运行时状态与错误信息，避免并发管理操作造成状态竞争。

### 7.3 未完成

1. ai-prod 的 C++ HTTP + C++ Runtime 主链路尚未在当前代码中完成替换，当前虽已完成 P9-P18 范围内的交付主链路 / catalog / pool / drain / license / infer 热路径 / 真实插件执行 / 启动 bootstrap / runtime 状态机 / reload/rollback 管理闭环 / 内部验收外壳 / 交付规范收敛，但插件生命周期深化与最终运行时替换仍未完成。
2. ai-license-mgr 与 ai-prod 的运行时 License 规则尚未完全统一到同一实现基线。
3. ai-test 尚未形成完整的生产镜像验收测试链路。
4. SDK、tools、docs、mount_template 与摘要 schema 仍可继续按最终交付目标细化。

### 7.4 阶段小结

当前平台已具备内部研发测试流程的基础版闭环能力。随着 ai-prod 完成 P9-P18、ai-builder 完成 B9/B10/B11，平台一侧已经具备交付主入口、能力目录管理、轻量实例池状态维护、交付级验收脚本、标准 `delivery_package/` 目录输出、ai-prod 生产镜像构建上下文 tarball、挂载模板、验收/运维工具、部署文档，以及验收清单、版本清单、交付摘要等最终收口物料；同时 ai-prod 的 infer 热路径已在 snapshot 可用时由 C++ 直接完成请求解析、license quick check、设备选择、实例池借还、真实插件动态加载执行、结果生成与基础日志审计，启动阶段的 bootstrap 首次装载与 reload/rollback 管理链路也已由 C++ 直接完成资源扫描、revision/operation SQLite 持久化、runtime snapshot 初始/重写与 catalog/pool 刷新，并进一步补齐 runtime 显式状态机与切换互斥保护，Python/React 页面已明确退化为仅供内部测试验收使用的外壳。后续实现将继续以当前平台为主平台、以 `ai_platform` 为运行内核与交付规范参考实现，推进真实 C++ Runtime 的最终替换，并继续细化交付 schema 与现场验收闭环。
