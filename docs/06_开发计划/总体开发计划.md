# 总体开发计划

## 1. 计划目标

按照“上层平台完整、运行底座扎实”的目标分阶段推进平台建设：保留当前平台在内部研发测试流程上的优势，重点吸收 `ai_platform` 在 Runtime 内核、交付目录与验收体系、生产侧 License / 热更新 / 回滚机制方面的成熟设计。

## 2. 计划状态说明

- 状态值：未开始 / 进行中 / 已完成 / 阻塞
- 当前版本状态：进行中（基础版闭环已完成，融合增强版已启动，当前完成文档与计划刷新）

## 4. 跨模块公共工作项

1. 建立 mono-repo 目录结构
2. 建立前后端基础工程
3. 建立共享元数据协议
4. 建立错误码、manifest、license schema
5. 建立 Docker 基础镜像与挂载目录模板
6. 建立 CI、质量检查与文档更新流程
7. 建立标准 `delivery_package/` 目录规范
8. 建立生产运行底座与内部测试外壳的分层边界

## 5. 进度跟踪要求

1. 每个模块实现前先核对设计文档与模块计划。
2. 实现前更新模块计划实际状态。
3. 实现完成后更新模块计划、总体计划与阶段小结。
4. 提交代码时使用中文提交说明。
5. 每轮实现完成后必须比对设计文档、开发计划与实际代码，确认未跑偏。

## 6. 当前里程碑结论

1. 基础版六个业务模块、单机交付 SDK、共享 schema、Docker 基础镜像、compose 编排与 CI 已完成。
2. 已完成与 `ai_platform` 的深度对比评估，并明确后续目标。
3. 当前已完成设计文档与开发计划的融合刷新，下一阶段进入运行底座与交付体系实现阶段。

## 7. 当前阶段进度更新

### 7.1 已完成

1. 已完成 P0-P8 首期基础版闭环实现。
2. 已完成 `ai_platform` 对比评估与评估报告输出。
3. 已完成产品设计、总体架构、技术选型、模块设计、总体开发计划与各模块开发计划刷新。
4. 已明确“内部研发平台 + 外部运行底座”的组合产品目标。
5. 已明确 ai-prod 下一阶段采用 C++ HTTP + C++ Runtime + 插件模式作为生产主链路。
6. 已明确 ai-builder 下一阶段输出标准 `delivery_package/`、工具、文档与验收材料。
7. 已明确 ai-license-mgr、ai-prod、SDK 在 License / 热更新 / 回滚 / 交付目录上的收敛方向。

### 7.2 进行中

1. 融合增强版整体计划已启动，当前首先从 ai-prod 开始推进 R2。
2. ai-prod 已开始首轮实施：新增 C++ HTTP 服务骨架，先代理现有 Python 接口，为后续 Runtime 替换做铺垫。
3. ai-prod 首轮实施已完成本地编译、CTest 与代理 smoke 验证，当前可作为后续 C++ Runtime 接入的过渡主链路骨架。
4. ai-prod 当前继续推进第二轮实施：增强 C++ HTTP 层分层结构，并补齐 rollback 管理路由兼容能力。
5. ai-prod 当前继续推进第三轮实施：让 health/capabilities/license 查询接口优先由 C++ 直读 runtime snapshot 响应，并保留自动降级转发。
6. ai-prod 当前已启动 P10 首轮：在 C++ 侧新增 capability catalog、轻量实例池骨架与 `/api/v1/admin/catalog` 诊断接口。
7. ai-prod 当前继续推进 P10 第二轮：让 infer 路由接入 capability catalog 与轻量实例池借还流程，并增加未知能力与池繁忙保护。
8. ai-prod 当前已完成 P10 第三轮：为 reload/rollback 接入实例池 drain 编排、切换等待与切换后 catalog/pool 刷新，P10 范围实现完成。

### 7.3 未完成

1. ai-prod 的 C++ HTTP + C++ Runtime 主链路尚未在当前代码中完成替换，当前虽已完成 P10 范围的 catalog / pool / drain 编排，但 Runtime 主链路仍主要由 Python 承担，后续继续收口 P9 与推进 P11。
2. ai-builder 尚未输出完整标准 `delivery_package/`。
3. ai-license-mgr 与 ai-prod 的运行时 License 规则尚未完全统一到同一实现基线。
4. ai-test 尚未形成完整的生产镜像验收测试链路。
5. SDK、tools、docs 与 mount_template 尚未完全按最终交付目标收敛。

### 7.4 阶段小结

当前平台已具备内部研发测试流程的基础版闭环能力。随着 ai-prod 完成 P10，C++ 侧已经具备能力目录管理、轻量实例池状态维护、infer 前置控制，以及 reload/rollback 期间的 drain 编排与刷新能力；后续实现将继续以当前平台为主平台、以 `ai_platform` 为运行内核与交付规范参考实现，进一步收口 C++ 主链路与 License/热更新/回滚的一致性。
