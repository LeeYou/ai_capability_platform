# 人脸检测与属性分析能力融合接入指南

> 版本：v1.0 | 分支：`feature/face_detect_attribute`

---

## 1. 架构概述

本次融合将 **face_detect**（YOLOv8n 人脸检测）和 **face_attribute**（MobileNetV3-Large 多任务属性分析）两个能力接入 `ai_capability_platform`，实现从训练、测试到生产推理的全链路闭环。

### 1.1 接入策略

在各子系统 `services/` 目录下新增 `capability_adapters/` 包，通过**适配器分发模式**接入真实 ML 逻辑：

| 子系统 | 适配器位置 | 分发入口 | 回退机制 |
|--------|-----------|---------|---------|
| ai-train | `services/capability_adapters/` | `execute_training_task()` | 模拟训练 |
| ai-test | `services/capability_adapters/` | `_simulate_case_execution()` | 仿真推理 |
| ai-prod (Python) | `services/capability_adapters/` | `infer()` | 哈希模拟推理 |
| ai-prod (C++) | `cpp/plugins/<capability>/` | `PluginExecutor::Execute()` | Python 回退 |

> **生产推理链路**：C++ proxy (`ai_prod_cpp_proxy`) 通过 `dlopen` 加载插件 `.so` → 调用 `ai_plugin_infer` → 如果插件不可用则回退到 Python backend。

### 1.2 两个能力定义

| 能力名称 | task_type | 模型架构 | 输入 | 导出格式 |
|---------|-----------|---------|------|---------|
| `face_detect` | detection | YOLOv8n | 图像 | ONNX / PyTorch |
| `face_attribute` | classification | MobileNetV3-Large | 人脸裁剪图 | ONNX / PyTorch |

```
datasets/face_detect/
├── images/
│   ├── train/          # WIDER FACE 训练图像
```

**YOLO 标注格式** (每行): `class_id cx cy w h` (归一化坐标)

```

```

### 3.2 face_attribute 数据集（CSV 格式）

```
datasets/face_attribute/
├── crops/              # 人脸裁剪图像
│   ├── 000001.jpg
│   ├── 000002.jpg
│   └── ...
├── train.csv           # 训练集标签
└── val.csv             # 验证集标签
```

**CSV 列定义**:

| 列名 | 类型 | 说明 | 取值 |
|------|------|------|------|
| image_path | string | 图像绝对路径 | - |
| glasses | int | 是否戴眼镜 | 0/1, -1=缺失 |
| mask | int | 是否戴口罩 | 0/1, -1=缺失 |
| hat | int | 是否戴帽子 | 0/1, -1=缺失 |
| integrity | int | 面部完整性 | 0/1, -1=缺失 |
| side_face | int | 是否侧脸 | 0/1, -1=缺失 |
| expression | int | 表情 | 0-3 (neutral/smile/sad/angry) |
| head_pose | int | 头部姿态 | 0-4 (front/left/right/up/down) |
| age | float | 年龄 | 0-100 |

## 4. 使用流程

### 4.1 Step 1: 初始化能力注册

```bash
# 确保 ai-train 服务已启动
python apps/shared/scripts/init_face_capabilities.py \
    --api-base http://localhost:26000 \
    --datasets-root /data/ai_capability_platform/datasets
```

### 4.2 Step 2: 创建训练任务（face_detect）

```bash
# 通过 API 创建训练任务
curl -X POST http://localhost:26000/api/v1/training-tasks \
  -H "Content-Type: application/json" \
  -d '{
    "capability_name": "face_detect",
    "task_name": "face_detect_v1",
    "framework": "ultralytics",
    "backend_type": "gpu",
    "train_params_json": "{\"epochs\": 50, \"batch_size\": 16, \"imgsz\": 640}"
  }'

# 执行训练（将调用真实 YOLOv8n 训练）
curl -X POST http://localhost:26000/api/v1/training-tasks/{task_id}/execute
```

### 4.3 Step 3: 创建训练任务（face_attribute）

```bash
curl -X POST http://localhost:26000/api/v1/training-tasks \
  -H "Content-Type: application/json" \
  -d '{
    "capability_name": "face_attribute",
    "task_name": "face_attribute_v1",
    "framework": "pytorch",
    "backend_type": "gpu",
    "train_params_json": "{\"epochs\": 30, \"batch_size\": 32, \"learning_rate\": 0.001, \"image_size\": 224}"
  }'

curl -X POST http://localhost:26000/api/v1/training-tasks/{task_id}/execute
```

### 4.4 Step 4: 注册模型产物

```bash
curl -X POST http://localhost:26000/api/v1/models \
  -H "Content-Type: application/json" \
  -d '{
    "capability_name": "face_detect",
    "model_version": "v1_0_0",
    "source_training_task_id": {training_task_id}
  }'
```

### 4.5 Step 5: 创建测试任务

```bash
curl -X POST http://localhost:26001/api/v1/test-tasks \
  -H "Content-Type: application/json" \
  -d '{
    "task_type": "single",
    "capability_name": "face_detect",
    "model_version": "v1_0_0",
    "requested_backend": "onnxruntime",
    "timeout_seconds": 30,
    "cases": [
      {"case_name": "test_001", "input_path": "test_images/face_001.jpg", "expected_output": ""}
    ]
  }'
```

### 4.6 Step 6: 生产推理

```bash
# 需要 ai-prod 服务先 bootstrap 装载能力
curl -X POST http://localhost:26004/api/v1/inference \
  -H "Content-Type: application/json" \
  -d '{
    "capability_name": "face_detect",
    "input_type": "image",
    "payload": "/path/to/test_image.jpg",
    "prefer_device": "gpu",
    "options": {"conf_threshold": 0.5}
  }'
```

## 5. 适配器协议

### 5.1 训练适配器协议 (TrainingAdapter)

```python
class TrainingAdapter(Protocol):
    def execute(
        self,
        *,
        capability_name: str,      # 能力名称
        task_type: str,             # 任务类型 (detection/classification)
        workspace_dir: Path,        # 训练工作目录
        dataset_path: str,          # 数据集路径
        export_dir: Path,           # 模型导出目录
        train_params: dict,         # 训练超参数
        log_callback: Callable,     # 日志回调
    ) -> dict[str, Any]:           # 返回 result_summary
        ...
```

### 5.2 测试推理适配器协议 (TestInferenceAdapter)

```python
class TestInferenceAdapter(Protocol):
    def infer(
        self,
        *,
        capability_name: str,       # 能力名称
        model_version: str,         # 模型版本
        model_artifact_path: str,   # 模型产物目录
        input_path: str,            # 输入文件路径
        task_type: str,             # 任务类型
    ) -> dict[str, Any]:           # 返回推理结果
        ...
```

### 5.3 生产推理适配器协议 (InferenceAdapter)

```python
class InferenceAdapter(Protocol):
    def infer(
        self,
        *,
        capability_name: str,       # 能力名称
        model_version: str,         # 模型版本
        model_root: str,            # 模型根目录
        input_type: str,            # 输入类型
        payload: str,               # 输入内容 (路径/base64)
        device: str,                # 设备 (cpu/gpu)
        options: dict,              # 推理选项
    ) -> dict[str, Any]:           # 返回推理结果
        ...
```

## 7. 多任务属性模型详细说明

### 7.1 网络结构

```
Input (3×224×224)
  └→ MobileNetV3-Large backbone (features)
     └→ AdaptiveAvgPool2d (960-dim)
        ├→ glasses   head → Linear(960, 2)   [二分类]
        ├→ mask      head → Linear(960, 2)   [二分类]
        ├→ hat       head → Linear(960, 2)   [二分类]
        ├→ integrity head → Linear(960, 2)   [二分类]
        ├→ side_face head → Linear(960, 2)   [二分类]
        ├→ expression head → Linear(960, 4)  [多分类]
        ├→ head_pose head → Linear(960, 5)   [多分类]
        └→ age       head → Linear(960, 1)   [回归]
```

### 7.2 损失函数

- **二分类/多分类**: CrossEntropyLoss (per-sample, masked)
- **回归 (age)**: MSELoss (per-sample, masked)
- **缺失标签**: 通过 mask=0 机制在 loss 计算中排除

### 7.3 推理输出示例

```json
{
  "glasses": {"label": "no", "class": 0, "confidence": 0.9521},
  "mask": {"label": "no", "class": 0, "confidence": 0.8734},
  "hat": {"label": "yes", "class": 1, "confidence": 0.7612},
  "integrity": {"label": "yes", "class": 1, "confidence": 0.9102},
  "side_face": {"label": "no", "class": 0, "confidence": 0.8891},
  "expression": {"label": "smile", "class": 1, "confidence": 0.8234},
  "head_pose": {"label": "front", "class": 0, "confidence": 0.9456},
  "age": {"value": 28.3}
}
```

## 8. C++ 推理插件架构

### 8.1 插件 ABI 协议

每个能力的生产推理通过 C++ 动态库（`.so` / `.dll`）实现，遵循 `ai_plugin_api.h` 定义的标准 C ABI：

| 符号 | 签名 | 说明 |
|------|------|------|
| `ai_plugin_init` | `(AiPluginInitParams*, AiPluginHandle*) → int` | 加载模型、初始化推理引擎 |
| `ai_plugin_destroy` | `(AiPluginHandle) → int` | 释放资源 |
| `ai_plugin_infer` | `(AiPluginHandle, AiPluginInput*, AiPluginOutput*) → int` | 执行推理 |
| `ai_plugin_free_result` | `(AiPluginOutput*) → void` | 释放推理结果内存 |
| `ai_plugin_get_info` | `(AiPluginHandle, AiPluginInfo*) → int` | 返回插件元信息 |
| `ai_plugin_warmup` | `(AiPluginHandle) → int` | 预热（可选） |
| `ai_plugin_health_check` | `(AiPluginHandle) → int` | 健康检查（可选） |
| `ai_plugin_reload` | `(AiPluginHandle, const char*) → int` | 热更新模型（可选） |

### 8.2 插件源码位置

```
apps/ai-prod/cpp/plugins/
├── face_detect/
│   ├── CMakeLists.txt
│   ├── include/face_detect_plugin.h
│   └── src/face_detect_plugin.cpp      # YOLOv8n ONNX 推理
│       - Letterbox 预处理 (640×640)
│       - ONNX Runtime Session 推理
│       - YOLOv8 后处理 + NMS
│       - 输出: {"objects":[...], "object_count": N}
│
└── face_attribute/
    ├── CMakeLists.txt
    ├── include/face_attribute_plugin.h
    └── src/face_attribute_plugin.cpp    # MobileNetV3 多任务 ONNX 推理
        - ImageNet 归一化预处理 (224×224)
        - ONNX Runtime Session 推理
        - 多头 Softmax + 回归解析
        - 输出: {"attributes":{...}}
```

### 8.3 编译构建

```bash
# 仿真模式（无 ONNX Runtime 依赖，用于 ABI 校验 / CI）
cd apps/ai-prod/cpp
cmake -B build -DONNXRUNTIME_ENABLED=OFF -DAI_PROD_CPP_BUILD_PLUGINS=ON
cmake --build build

# 生产模式（启用 ONNX Runtime 真实推理）
cmake -B build \
  -DONNXRUNTIME_ENABLED=ON \
  -DONNXRUNTIME_ROOT_DIR=/opt/onnxruntime-1.18.1 \
  -DAI_PROD_CPP_BUILD_PLUGINS=ON
cmake --build build
```

编译产物位于 `build/plugins/face_detect/` 和 `build/plugins/face_attribute/`。

### 8.5 推理数据流

```
HTTP 请求 → C++ http_server
  → CapabilityCatalog.GetEntry(capability_name)
  → PluginExecutor.Execute()
      → dlopen(binary_path)
      → ai_plugin_init(model_dir, device)
      → ai_plugin_infer(input, &output)    ← ONNX Runtime 推理
      → ParsePluginResult(output)
  → JSON 响应
```

## 9. 扩展新能力

按以下步骤为平台新增一个真实 ML 能力：

1. 在 `ai-train/services/capability_adapters/` 创建 `{name}_train.py`，实现 `TrainingAdapter` 协议
2. 在 `ai-test/services/capability_adapters/` 创建 `{name}_test.py`，实现 `TestInferenceAdapter` 协议
3. 在 `ai-prod/services/capability_adapters/` 创建 `{name}_infer.py`，实现 `InferenceAdapter` 协议
4. 在 `ai-prod/cpp/plugins/{name}/` 创建 C++ 推理插件，实现 `ai_plugin_api.h` ABI
5. 在各 `__init__.py` 的 `_auto_register()` 中注册 Python 适配器
6. 更新 `ai-prod/cpp/CMakeLists.txt` 添加插件子目录
7. 更新 Dockerfile 添加新依赖
8. 运行初始化脚本注册能力并绑定数据集

**无需修改平台核心代码**——Python 分发逻辑已内置，C++ proxy 通过目录扫描自动发现插件。
