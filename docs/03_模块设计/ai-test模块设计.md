# ai-test 模块设计

## 1. 模块目标

建设面向内部研发验收的测试子系统，支持单接口测试、批量测试、生产镜像验收测试、测试报告生成与导出。

## 2. 模块职责

1. 从 ai-train 查询模型与能力信息
2. 执行模型测试与批量测试
3. 对生产镜像执行 API 回归与验收测试
4. 生成结构化测试报告
5. 持久化测试结果与报告

## 3. 逻辑组件

1. Web 前端：单测页面、批测页面、镜像验收页面、报告中心
2. API 服务：模型查询代理、测试任务管理、报告导出
3. 测试执行器：自动匹配能力与推理实现
4. 验收执行器：面向 ai-prod C++ HTTP 服务执行回归测试
5. 报告引擎：生成研发验收 / 交付验收双视角的 HTML/PDF/JSON 报告
6. 性能基线管理器：维护 C++ HTTP 主服务的性能/稳定性验收阈值模板

## 4. 核心数据

1. `test_task`
2. `test_case`
3. `test_result`
4. `test_report`
5. `acceptance_task`
6. `acceptance_script_result`
7. `performance_baseline`

## 5. 关键流程

1. 拉取能力与模型信息
2. 用户选择模型、测试集或目标镜像
3. 自动匹配对应推理代码或生产 API
4. GPU 优先执行，失败时回退 CPU
5. 持久化结果并生成报告
6. 输出研发验收报告与交付验收报告
7. 统一编排 `acceptance_check.py` 与 `pressure_smoke.py` 等生产验收脚本
8. 对性能/稳定性验收结果执行基线比对并沉淀到报告

## 6. 接口要求

1. 模型列表同步接口
2. 单接口测试接口
3. 批量测试接口
4. 测试报告查询/导出接口（支持研发验收 / 交付验收模板切换）
5. 生产镜像验收任务接口

## 7. 非功能要求

1. 测试执行具备超时控制
2. 测试结果可复现
3. 报告导出稳定可追溯
4. 多能力测试隔离执行
5. 验收测试需要兼容未来 C++ HTTP 主服务
6. 需要支持可追溯的性能/稳定性基线模板

## 8. 设计决策

1. 内部测试采用 Python + ONNX Runtime。
2. 统一测试样本输入抽象，支持图片、视频、PDF、其他文件类型。
3. 报告模板需同时面向研发验收和交付验收，并支持同一任务在双视角下切换导出。
4. 对生产镜像的验收优先通过 C++ HTTP API 执行，而不是依赖 Python 模拟运行逻辑。
5. 性能/稳定性验收优先采用默认阈值模板，并允许按 capability 覆盖。

## 9. 整改设计与跟踪

### 9.1 当前整改重点

1. 已建立测试样本输入与训练标注 schema 的映射关系，避免训练 / 测试样本语义脱节。
2. 已建立模型版本、插件版本、license 记录、运行时 revision 与测试报告之间的统一证据链。
3. 已为新增能力提供模板化回归、验收与交付报告结构。
4. 已显式区分真实测试与仿真回退路径，在任务、结果、证据链与报告中统一输出 `execution_mode` 与风险提示；生产验收路径也已补齐真实执行证据，避免报告误判。
5. 已将 `test_service.py` 收敛为任务编排层，新增 `test_execution_service.py` 负责执行模式判定与单用例执行；测试报告摘要已接入 shared contract validator，核心单测/批测链路的 `commit in loop` 已收敛为明确事务边界。

### 9.2 与其他模块的关键契约

1. 消费 ai-train 输出的能力元数据、模型包 manifest、测试样本适配信息。
2. 消费 ai-prod 暴露的稳定授权状态、运行时状态、revision 与诊断信息。
3. 消费 ai-builder 输出的交付材料与构建清单，校验可装载性和交付一致性。
4. 必须复用 shared contract validator 校验模型包、交付物和报告关键契约，避免继续分散手写字段检查。

## 10. Web 产品化设计补充

### 10.1 页面定位

1. `ai-test` 是当前最需要产品化收口的模块，目标是从“展示 / 看板页”升级为真正可执行的测试工作台。
2. 页面应承担训练结果后的评估中枢，以及生产测试主入口。
3. 模块首页需要优先回答三个问题：哪些模型待测、哪些测试失败、哪些模型可进入授权 / 构建。

### 10.2 页面结构

1. 概览页：待测模型、最近测试、失败分布、验收结论、下一步动作。
2. 单测工作台：
   - 左侧模型选择与输入配置
   - 中间输入预览 / 在线推理结果
   - 右侧指标摘要、错误说明、样本回流入口
3. 批量测试页：
   - 测试任务列表
   - 测试集 / 阈值 / 模板配置向导
   - 进度、结果摘要、失败样本聚类
4. 生产验收页：
   - 验收任务列表
   - 目标环境 / 镜像 / 基线选择
   - acceptance / pressure 日志与结论
5. 报告中心：
   - 研发验收 / 交付验收双视角切换
   - 证据链、导出记录、推荐下一步（授权 / 构建）

### 10.3 关键交互要求

1. 测试任务创建必须采用向导式流程，避免用户手动组织零散参数。
2. 结果页必须突出“通过 / 不通过 / 风险项 / 推荐动作”，而不是只堆图表。
3. 错误样本需要支持回流标注、重新测试、与历史模型对比。
4. 测试通过模型需要有显式“推送到授权 / 构建”入口，避免人工记录模型 ID。
