# ai-train 模块设计

## 1. 模块目标

建设面向内部研发流程的训练子系统，提供样本标注、训练任务管理、模型管理、能力元数据管理和训练模板管理能力，为后续测试、构建和交付提供高质量输入。

## 2. 模块职责

1. 数据集挂载与目录识别
2. 样本标记任务管理
3. 训练任务创建、执行、跟踪
4. 模型产物登记与版本管理
5. 对 ai-test、ai-builder 提供能力与模型查询 API
6. 管理端提供专业化标注台、训练台、模型管理台

## 3. 逻辑组件

1. Web 前端：标注台、训练台、模型管理台
2. API 服务：任务、模型、能力、数据集管理
3. 训练执行器：容器内训练任务调度
4. 能力模板管理器：新增能力模板、训练脚手架、模型包模板
5. 数据持久化层：SQLite + 文件系统

## 4. 核心数据

1. `capability_registry`
2. `dataset_binding`
3. `annotation_task`
4. `training_task`
5. `model_artifact`
6. `training_template`

## 5. 关键流程

1. 扫描 `/data/ai_capability_platform/datasets/`
2. 绑定能力与数据集
3. 创建标注任务并保存结果
4. 发起训练任务
5. 产出部署模型、manifest 与模型元数据
6. 发布模型信息给 ai-test、ai-builder 查询
7. 保证模型包格式与交付运行底座兼容
8. 提供样本级标注编辑、训练日志回显、执行计划展示与交付 manifest 预览

## 6. 接口要求

1. 能力列表接口
2. 模型列表接口
3. 模型详情接口
4. 训练任务创建/查询接口
5. 数据集状态接口
6. 标注任务创建/查询/提交接口

## 7. 非功能要求

1. 支持 CUDA 11.8
2. 支持训练日志持久化
3. 支持任务失败重试和状态跟踪
4. 标注与训练操作审计可追踪
5. 页面交互适合内部研发长流程作业
6. 模型包需内置预处理、阈值、标签、校验文件与交付元数据

## 8. 设计决策

1. 训练代码采用 Python。
2. 首期训练框架优先 PyTorch。
3. 模型导出统一为部署模型包格式，而非直接交付 checkpoint。
4. 新增能力时必须同步产出训练模板、测试模板、推理模板、模型 manifest 模板。
5. ai-train 只负责内部生产线，不直接承担客户交付运行逻辑。

## 9. 整改设计与跟踪

### 9.1 当前整改重点

1. 已建立按任务类型分层的标注 schema，统一支持 classification、detection、OCR、structured_extraction 四类任务结构。
2. 已建立“标注结果 → 训练输入 → 模型导出 → 模型包 manifest”的统一适配器链路，并在训练工作区中输出 `training_input.json`、`template_bundle.json` 与 `model_export_spec.json`。
3. 已将训练流程从工作区脚手架收敛为可执行的训练运行器与导出链路，支持生成日志、结果摘要与导出目录。
4. 已建立新增能力模板，统一输出训练模板、测试模板、推理模板、构建模板与 manifest 模板。
5. 已显式区分真实训练与模板 / 仿真训练路径，在任务、日志、结果摘要、执行计划与前端界面中统一输出 `execution_mode`。
6. 已将训练领域拆分为任务编排、工作区准备、执行调度、结果写入与契约校验子服务，并开始通过 shared contract validator 收敛结果契约校验与关键事务边界。

### 9.2 与其他模块的关键契约

1. 向 ai-test 输出稳定的测试样本映射、模型包 manifest 与能力元数据。
2. 向 ai-builder 输出可直接用于真实插件构建的模型包、manifest、labels、preprocess、validation 产物。
3. 向 ai-prod / ai-sdk 输出可被 runtime 强消费的模型包字段，而不是只提供展示型元数据。
4. 已优先复用 shared contract validator 校验训练结果摘要，避免在训练服务内继续散落手写关键字段校验逻辑，并为后续模块复用保留统一入口。

## 10. Web 产品化设计补充

### 10.1 页面定位

1. `ai-train` 是内部研发主工作台，不应再表现为“接口演示页”。
2. 页面需要围绕“数据集 → 标注任务 → 训练任务 → 模型资产”形成连续操作闭环。
3. 首页优先展示待处理标注、运行中训练、最新模型与待测试动作。

### 10.2 页面结构

1. 概览页：项目 / 能力统计、数据集分布、近期任务、异常提醒、下一步跳转。
2. 数据集页：数据集绑定、样本规模、任务类型、数据质量、训练/验证/测试划分概览。
3. 标注工作台：
   - 左侧样本列表
   - 中间画布 / 表单编辑区
   - 右侧标签、属性、质检提示、快捷键说明
4. 训练工作台：
   - 训练任务列表
   - 参数与执行计划面板
   - 实时日志 / 指标 / 结果摘要标签页
5. 模型资产页：
   - 模型卡片 / 列表
   - manifest / runtime contract / 导出文件详情
   - “送测”快捷入口

### 10.3 关键交互要求

1. 标注台优先支持样本级保存、批量提交、校验提示、异常恢复。
2. 训练台优先支持 prepare / execute、阶段状态、日志搜索、失败重试。
3. 模型资产页优先支持最佳版本标记、产物对比、直接跳转 ai-test。
4. 所有任务详情页都应展示上游数据集、下游测试入口与关联对象，而不是只展示 JSON 字段。
