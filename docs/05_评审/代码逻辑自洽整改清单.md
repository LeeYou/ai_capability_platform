# 代码逻辑自洽整改清单

## 1. 文档目标

基于本轮代码审查结论，统一梳理平台在“标注 → 训练 → 测试 → 构建 → 授权 → 推理运行 → SDK 交付”主链路上的逻辑不自洽点，形成后续逐模块推进整改的唯一清单，并作为设计文档、开发计划文档和阶段进度更新的共同依据。

## 2. 审查结论摘要

### 2.1 训练 / 测试 / 推理 SO 主链路

1. `ai-train` 当前以训练脚手架、工作区准备和模型包元数据登记为主，尚未形成可直接驱动真实能力插件构建的训练执行闭环。
2. `ai-builder` 当前仍包含模板化构建与占位产物输出，尚未完全切换为“基于真实能力源码 / 插件源码 / 模型包契约”的工业级构建链路。
3. `ai-prod` 已具备成熟的 C++ Runtime / 插件装载 / 推理主链路，但模型包 manifest、插件 ABI、builder 交付物之间仍缺少统一强约束契约。

### 2.2 授权生成 / 校验 / 运行时授权校验

1. `ai-license-mgr`、`ai-prod` Python、`ai-prod` C++ 在签名 canonical JSON、硬件指纹、版本约束语义上已基本对齐。
2. 当前缺少“签发侧真实产物 → C++ runtime / SDK / license_tool”统一使用的金标准测试向量与跨模块回归证据链。
3. 若最终交付要求“核心逻辑以 C++ 动态库封装为准”，则授权领域仍需进一步收敛 C++ 侧公共核心与稳定诊断接口。

### 2.3 标注系统 / 已知模型框架 / 新增能力全流程

1. 当前标注结构较宽松，尚未形成按任务类型分层的标准 schema。
2. 训练框架、训练模板、模型包导出、测试样本适配、运行时插件输入之间缺少统一模板化约束。
3. 当前还不满足“随时新增单独 AI 能力，并稳定贯通样本标记、训练、测试、推理、生产”的工业级要求。

## 3. 整改原则

1. **按模块推进**：每次只推进一个模块或一个明确的跨模块闭环，不并行铺开过多改造面。
2. **文档先行**：实现前先更新模块设计文档、模块开发计划、总体计划与本整改清单。
3. **契约优先**：先收敛 schema、ABI、manifest、license、报告和交付目录契约，再进入实现。
4. **C++ 核心优先**：凡涉及最终交付主链路、授权校验、运行时推理、SDK 集成的核心逻辑，优先落到 C++ 公共核心或稳定 C ABI 契约。
5. **证据闭环**：每项整改完成后，必须同时更新代码、测试、设计文档、开发计划、总体阶段小结。

## 4. 进度跟踪规则

1. 状态值统一使用：`未开始 / 进行中 / 已完成 / 阻塞`。
2. 本清单中的整改编号必须在对应模块设计文档与模块开发计划中建立映射。
3. 每次开始实现前：
   - 核对对应模块设计文档；
   - 核对对应模块开发计划；
   - 根据实际代码更新计划状态。
4. 每次实现完成后：
   - 对照本清单完成自查；
   - 更新模块计划实际进度；
   - 更新总体计划与阶段小结；
   - 以中文提交阶段总结。

## 7. 逐模块实施顺序建议

1. **第一阶段：ai-train**
   - 优先统一标注 schema、训练输入适配器、模型包契约。
2. **第二阶段：ai-license-mgr**
   - 优先统一授权核心、金标准测试向量与稳定诊断接口。
3. **第三阶段：ai-builder**
   - 优先切换真实插件构建链，去除主链路占位产物。
4. **第四阶段：ai-prod**
   - 优先收敛 manifest / plugin / license 的 C++ 运行时强校验与强消费。
5. **第五阶段：ai-test**
   - 优先形成端到端验收证据链与新增能力回归模板。
6. **第六阶段：ai-sdk**
   - 最后完成 SDK 与生产主链路的一致性交付收口。

## 8. 本轮文档刷新结论

1. 已建立整改清单文档，作为后续逐模块推进的统一基线。
2. 已要求总体架构、模块设计、总体计划、模块计划全部建立与本清单的映射关系。
3. 从本轮开始，平台进入“整改设计清晰化 + 按模块逐步实施”的新一轮增量阶段。
4. 当前已完成 ai-train 模块整改闭环：已补齐任务类型化标注 schema、训练输入适配、训练执行与导出链路、模型 manifest/runtime 契约以及统一模板脚手架。
5. 当前已完成 ai-prod 的 RP-01：C++ runtime resource scanner 与 Python 验收外壳已对 ai-train 模型包 manifest、ai-builder 插件 manifest 建立强校验与失败留痕，无效资源不会进入 bootstrap / reload 运行时能力集。
