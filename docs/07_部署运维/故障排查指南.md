# 故障排查指南

## 1. docker compose 启动失败

1. 先执行 `docker compose config`
2. 检查端口 26000-26005 是否冲突
3. 检查 `AI_CAP_HOST_ROOT` 是否为绝对路径
4. 如仅 ai-prod 异常，需额外确认容器内 `26014` 未被其它进程占用

## 2. 服务健康检查失败

1. 使用 `docker compose ps` 查看容器状态
2. 使用 `docker compose logs <service>` 查看日志
3. 使用 `bash scripts/docker/health_check.sh` 逐项验证

## 3. ai-builder / ai-sdk 无法生成产物

1. 确认 `models/` 目录存在目标模型包
2. 确认 `license/` 目录存在标准 `license.bin` 与 `pubkey.pem`
3. 确认 `libs/<target>/<capability>/` 结构满足 `lib/include/license/manifest`

## 4. schema 不兼容

1. 先运行 `python -m unittest discover -s apps/shared/tests -v`
2. 检查示例文件是否仍覆盖所有必填字段
3. 检查 manifest/license 结构变更后是否同步更新共享 schema

## 5. ai-prod 交付验收/压测失败

1. 先确认 `apps/ai-prod/config/prod_defaults.env` 中的端口、宿主机目录、snapshot 路径与现场一致
2. 先运行 `python3 apps/ai-prod/scripts/acceptance_check.py --base-url http://127.0.0.1:26004`
3. 再运行 `python3 apps/ai-prod/scripts/pressure_smoke.py --base-url http://127.0.0.1:26004 --path /api/v1/health`
4. 若 `/api/v1/admin/revisions` 仍然可访问，说明内部接口边界被破坏，需要回查 ai-prod C++/backend 路由配置
5. 若 ai-prod `/api/v1/health` 不通，但容器仍在运行，优先检查 `run_prod_stack.sh` 是否已拉起 Python backend 26014 与 C++ 主进程
6. 若 infer 压测失败，优先检查能力目录、license 范围、实例池大小与 runtime snapshot 是否匹配
